# WELCOME — Social/Contacts Interop + Developmental Matching (design v1)

Goal: WELCOME «дружит» со всеми соцсетями и контактами, настраивается за минуты, и матчит
не «похожих», а **полезно и развивающе** — с объяснением пользы для обеих сторон.

---

## Part A. Interop layer («дружба со всеми»)

### A1. Принципы (нерушимые)

1. **OAuth-first, link-only там, где API нет.** Где есть официальный API — используем его.
   Где нет — только ссылка/диплинк, никакого парсинга.
2. **Никакого скрейпинга** (LinkedIn-прецедент Proxycurl: засужен и закрыт). Только
   публичные API и действия самого пользователя.
3. **Всё подтверждает пользователь.** Импорт/обогащение → черновик → построчное подтверждение.
4. **Портативность.** Экспорт в vCard/CSV/JSON и «вынести в Google Contacts» по кнопке.
5. **Один реестр провайдеров.** Добавить интеграцию = один файл + строка в реестре.

### A2. Реестр провайдеров (единый контракт)

```ts
type ProviderId = 'telegram'|'whatsapp'|'email'|'google-contacts'|'google-calendar'
  |'microsoft-people'|'linkedin'|'github'|'instagram'|'x'|'vcard'|'ics'|'csv'|'luma'|'notion';
type Provider = {
  id: ProviderId;
  kind: 'channel'|'contacts'|'calendar'|'directory'|'publish';
  auth: 'oauth'|'bot'|'api-key'|'none';
  capabilities: Array<'send'|'receive'|'import'|'export'|'publish'|'deeplink'>;
  direction: 'out'|'in'|'both';
  status: 'live'|'disabled'|'planned';
  setup: { env: string[]; steps: string[] };   // показывается в UI «как подключить»
};
```

### A3. Матрица интеграций

| Провайдер | Kind | Auth | Capabilities | Статус | Примечание |
|---|---|---|---|---|---|
| Telegram | channel | bot | send, receive, deeplink | **live** | webhook + fast-path (1.5с), двусторонняя привязка |
| Email (Resend) | channel | api-key | send | **live** | OTP + сервисные уведомления; нужен домен для любых адресов |
| vCard (.vcf) | contacts | none | import, export | **live** | «Добавить в контакты» на карточке + импорт телефонной книги |
| CSV | contacts | none | import, export | **live** | импорт событий, экспорт организатора |
| ICS (календарь) | calendar | none | export, deeplink | **planned** | `.ics` события + «Добавить в Google/Apple Calendar» |
| Share-deeplinks | publish | none | publish | **planned** | Поделиться карточкой в X/WhatsApp/Telegram/LinkedIn (без API) |
| Google Contacts | contacts | oauth | import, export | **planned** | People API; нужен наш OAuth-клиент (GCP) |
| Google Calendar | calendar | oauth | import, export | **planned** | создание события/встречи по итогам знакомства |
| Microsoft People/Calendar | contacts, calendar | oauth | import, export | **planned** | Graph API |

### A4. Легкая настройка (что значит «очень легко»)

- Страница **`/me/connections`**: все провайдеры списком с иконкой, статусом
  (`подключено` / `подключить` / `скоро` / `недоступно`), кратким описанием, кнопкой
  «Подключить» и блоком «как подключить» (env-имена + шаги) — прямо из реестра.
- **Одна кнопка там, где возможно**: Telegram — привязка (есть), vCard/ICS/CSV — скачивание
  (мгновенно), OAuth-провайдеры — «Подключить» → согласие → готово.
- **Честные состояния**: если провайдер не настроен на инстансе — карточка говорит почему
  («нужен API-ключ владельца»), а не молчит.
- **Никаких сюрпризов**: на каждой карточке — что мы отправляем/получаем и чего не делаем
  («не парсим LinkedIn», «не читаем вашу почту целиком — только OTP и сервисные»).

## Part B. Matching v4: полезно и развивающе

### B1. От «похожих» к «полезным»

Текущий скоринг (v3): intent-комплемент + интересы + функция/отрасль. Добавляем две новые оси:

| Компонент | Смысл | Как считается |
|---|---|---|
| `intentFit` | закрывает твой запрос | комплемент need↔offer, вес = приоритет намерения (главное/второстепенное) |
| `interestOverlap` | общие темы | пересечение интересов / min(размеры) |
| **`complementarity`** | вы друг другу **полезны** асимметрией | матрица пар функций (founder↔investor, designer↔engineer, sales↔product) + пересечение «твои needs × их offers» по осям |
| **`goalAlignment`** | ведёт к твоей цели | цели пользователя (каталог ниже) → паттерны намерений/интересов; совпадение с профилем кандидата |
| **`novelty`** | не эхо-камера | штраф за совпадение функции/отрасли/набора интересов с уже показанными |
| `recency` | свежесть и доступность | активность, участие в событии, недавние opt-in |

`usefulness = 0.30·intentFit + 0.20·interestOverlap + 0.25·complementarity + 0.15·goalAlignment + 0.10·novelty`
(веса конфигурируемы по контексту: на событии выше intentFit/recency, вне события — goalAlignment).

### B2. Каталог целей (для goalAlignment и «развивающести»)

`learn-skill` · `find-mentor` · `become-mentor` · `find-cofounder` · `hire` · `get-hired` ·
`find-clients` · `get-more-clients` · `enter-market` · `fundraise` · `invest` ·
`find-partners` · `find-community` · `get-feedback` · `give-feedback` · `grow-network`

Цель хранится у профиля (≤3, выбирается из каталога), видна только участнику и используется
только для его рекомендаций (не публикуется, не показывается другим — приватность).

### B3. Причины «полезности» и развития

Каждая рекомендация объясняется **двумя** строками:
- **Польза:** «Закрывает твою цель „войти в EU-рынок“ · она в retail в Испании · вы оба в AI»
- **Развитие:** «Можешь научиться: RAG-системы (её сильная сторона — твой интерес)» ИЛИ
  «Она ищет ментора по AI-трансформации — ты готов менторить».

### B4. Режимы подбора (UI)

| Режим | Что показывает |
|---|---|
| **Полезные сейчас** | максимум `usefulness` (дефолт) |
| **Расти** | люди, у которых можно научиться искомому (learning-goal × их сильные стороны) |
| **Похожие на меня** | peer-нетворкинг: совпадение функции/отрасли/интересов |
| **Шире круга** | наоборот, максимальная новизна: другие отрасли/функции при общей теме |

### B5. Развивающие механики (после встречи)

- Заметки и «следующий шаг» (есть) + напоминание «что ты хотел сделать» через N дней.
- Итог знакомства: «что вы обсудили / чему научились» — приватная запись, которая питает
  личные рекомендации (и только их).
- Мягкий недельный дайджест (по согласию): «3 человека, полезных для твоей цели X».

## Part C. Приватность и контроль (нерушимо)

- Цели, заметки, история раскрытий — приватны; в публичную карточку не попадают.
- Импорт из адресной книги: только «кто из твоих контактов уже здесь» — без загрузки чужих данных.
- OAuth-токены — только на сервере, шифруются; никаких токенов в браузере и логах.
- Любая отправка — только по согласию (`service_channel` / `organizer_marketing`) и только
  выбранным каналом.

## Part D. Дорожная карта

**Фаза 1 — без внешних ключей (можно начинать сразу)**
1. Реестр провайдеров + страница `/me/connections` (статусы, «как подключить», честные состояния).
2. ICS для событий (`.ics` + «добавить в календарь») и кнопка «Добавить в контакты» (.vcf) на карточке.
3. Share-диплинки (X/WhatsApp/Telegram/LinkedIn) с OG-превью.
4. Цели профиля (каталог ≤3) + matching v4 (goalAlignment, complementarity, novelty) + 4 режима + двухстрочные причины. Тесты, i18n EN/RU/ES.

**Фаза 2 — нужен наш OAuth-клиент (GCP/Microsoft, 15–20 минут владельца)**
5. Google Contacts (People API): импорт «кто уже здесь» и экспорт выбранных контактов.
6. Google Calendar / Microsoft Graph: встреча по итогам знакомства.

Пошаговая инструкция для владельца (consent screen, scopes, redirect URIs, имена переменных):
[GOOGLE_OAUTH_SETUP.md](GOOGLE_OAUTH_SETUP.md). До этих креденшелов «кто уже здесь» уже
отвечает импорт адресной книги (.vcf/CSV) без OAuth — см. §A3 строки vcard/csv, capability
`match`.

**Фаза 3 — по решению владельца**
7. WhatsApp Business API (если нужен реальный канал), LinkedIn OIDC (базовый), Luma API.

**Фаза 4 — развитие и удержание**
8. Недельный дайджест (по согласию) и напоминания о «следующем шаге».
