# Конкурс: проверка условий и сценарий показа
## Статус
Источник первого ТЗ указывает 7 сентября 2026 и упоминание @AutoClawAIer. Официальная страница AutoClaw подтверждает сам продукт, но проверенные правила данной кампании, дедлайн/часовой пояс, форма и критерии жюри не получены. Не утверждать, что приём заявок открыт. Не заявлять гарантированную победу.

Release blocker конкурса: получить официальный источник и зафиксировать exact URL, скрин/текст правил, deadline with timezone, eligibility, prior-work/reuse rules, обязательные hashtags/mentions, формат demo и submit destination. Не менять дату в артефакте по предположению.

## Показ продукта — 90 секунд как редакционный формат
00–15: «На мероприятиях мы собираем контакты, но теряем контекст. Здесь один личный QR остаётся с человеком».
15–30: открыть личную карточку на чужом телефоне без аккаунта; скачать выбранные контакты.
30–45: показать предрегистрацию: данные уже есть, человек подтверждает цель встречи, не заполняет всё заново.
45–65: два разных пользователя видят причину рекомендации; один предлагает, второй принимает; закрытые контакты только теперь доступны.
65–80: следующий шаг остаётся после мероприятия; тот же личный QR работает вне него. Организатор видит агрегаты, не личную переписку.
80–90: показать tests/release SHA и какой вклад реально выполнен AutoClaw. Неподключённый WhatsApp API обозначить честно.

Это сценарий записи, не обещание длительности разработки. Для текущего preview все демонстрационные действия подписаны DEMO. Для конкурсного production-показа заменить их реальными двумя тестовыми аккаунтами и live channel evidence.

## Черновик публикации — НЕ ОТПРАВЛЕН
«Собрал WELCOME: один личный QR для любых встреч. Перед мероприятием — профиль из регистрации, во время — объяснимые рекомендации, после — следующий шаг. Контакты открываются по вашему выбору, без обязательной установки приложения. [Фактическая роль AutoClaw]. Демо: [VERIFIED_PUBLIC_URL]. Проверки и ограничения: [EVIDENCE_URL]. [Упоминания только после проверки правил]».

Не использовать mock-users как traction, гипотетические проценты как результаты и чужие библиотеки как полностью собственный код.
