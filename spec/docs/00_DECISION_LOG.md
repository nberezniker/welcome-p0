# Что исправлено относительно исходного ТЗ
Основание: приложенный документ «Welcome Bot для мероприятий», версия 1.0.

| Исходное утверждение | Решение версии 2 | Почему |
|---|---|---|
| QR → уже знаем человека, ноль полей | Узнаём только по подтверждённой сессии/каналу; импортированный профиль нужно безопасно присвоить | QR сам по себе не удостоверяет личность |
| LinkedIn подтянет всё | URL профиля — вручную; OIDC — только доступные поля; рабочие данные человек подтверждает | Официальный sign-in не равен полной выгрузке опыта |
| Бот обязателен для получения чужой карточки | Публичная разрешённая карточка сразу видна в браузере | Не ломать самое ценное первое действие |
| `users.event_id` | Независимые `profiles` и `event_memberships` | Один человек приходит на много событий и пользуется QR вне событий |
| Все контакты организатору и массовый обмен | Раздельные подписки; opt-in каталог; персональные приватные знакомства | Согласие на мероприятие не равно разрешению на любой маркетинг |
| Sheets — основная база | PostgreSQL, транзакции, ограничения, RLS; CSV как переносимый интерфейс | Одновременные подтверждения, приватность и повторные webhook |
| Пост-ивент, QR и mutual match уникальны | Это базовые функции; WITR/Fotify/Eventscase/Blinq уже пересекаются с идеей | Нельзя строить презентацию на ложном отсутствии конкурентов |
| OpenClaw — обязательный runtime | Обычный web/backend; AutoClaw — инструмент изготовления | Не превращать каждого пользователя в сессию привилегированного AI-агента |
| Welcome-бот уже есть в GitHub | В доступных проверках не идентифицирован; переиспользование только по read→test→adapt | Название файла или старый текст не доказывают наличие кода |
| Один prompt гарантирует production | Один утверждённый пакет + несколько внутренних циклов + обязательные внешние доступы | Не подменять автономность магией |
| Почти бесплатно, выиграем | Ограниченный бюджет и проверяемый результат; победа не гарантируется | Инфраструктура, поддержка и сообщения имеют себестоимость |

## Метки достоверности
**Источник** — прямо прочитанные материалы/официальная документация. **Решение** — выбранная конструкция нового продукта. **Гипотеза** — предположение для проверки рынком. **Не проверено** — нет достаточных данных или реального запуска. Эти категории не смешиваются.
